# 每日账单自动下载计划

控制端0.13 / 数据库迁移v13增加支付宝和微信的每日下载计划。每个渠道分别设置收款、退款计划，共四项，初始全部停用，默认执行时间为北京时间10:00。计划只生成已有的[官方下载任务](native-bills.md)，下载后沿用账单导入、来源记录和差异报告；不会确认付款、执行退款或改变订单、权益。

## 配置与执行

部署时先按[支付接入](payments.md)配置目标商户，并显式设置 `BILL_DOWNLOADS_ENABLED=true` 后重启。该开关同时控制按需下载消费者和每日调度器，默认关闭。随后由管理员或财务在“商户账单”的自动下载计划中启用所需渠道和账单类型，填写北京时间 `HH:MM`。配置保存只代表计划已保存，任务排队也不代表账单已导入。

计划固定使用 `Asia/Shanghai`，不随服务器或浏览器时区变化。业务日期D的账单在D+1日的配置时间开始排队。例如执行时间10:00时，10月27日账单在10月28日北京时间10:00到期；若10月28日11:00才启用，首个日期仍为10月27日，可立即排队。若在当日执行时间前启用，则等待当日时间到达。

启用或停用后重新启用，从北京时间昨天开始，不追溯更早历史。同一商户的已启用计划修改时间或授权人时，保留尚未推进的账单日期；明确改用新商户重新授权时，从昨天开始，不继承旧商户的进度。服务中断后，只补排最近7个已结束的北京时间业务日期；更早的缺口需要通过按需入口处理，按需下载仍限最近90天。计划列表的 `next_bill_date` 表示下一张待排队账单的业务日期，不是任务实际完成时间；对应计划时间是该日期次日的 `run_at`。

同一渠道、账单类型、日期和商户身份仍只有一个稳定下载任务。调度器只插入缺失任务，遇到已有按需任务、成功任务或 `manual_required` 任务时不接管、不重新排队，推进计划游标。游标、任务和审计在同一事务中提交，多实例不能因此重复生成任务。已有任务的失败退避、8次错误或7天期限以及格式不兼容直接转人工规则保持不变。转人工后须检查原因并明确按需重试，不会每天自动重新开启失败任务。

## 授权与暂停

保存启用计划时，服务端记录当前操作者、账号安全版本和配置中的商户身份指纹。浏览器不能提交授权人、商户指纹、下载地址、凭据、历史游标或任务状态。调度不使用无归属的系统管理员身份。

账号被降权、密码或安全版本变更、渠道未配置或商户身份变化时，计划自动暂停，分别显示 `actor_changed`、`provider_unavailable` 或 `merchant_changed`。不会静默改用新商户或新的授权账号。修正原因后，当前管理员或财务需要明确重新启用。

停用、重新启用或更换授权账号会更新内部授权代次，撤销尚未完成的旧自动任务；任务外呼前和导入提交时都检查有效计划授权。已经开始的只读外部请求可能完成，但失效授权不能提交导入。原授权账号仅修改执行时间，且安全版本和商户身份不变时，保留授权代次，已有任务继续有效。已成功导入的历史账单与来源记录不因停用而删除。

旧自动任务转人工后，可由当前管理员或财务通过按需入口重试相同日期；沿用原任务ID，并改为本次按需授权，不再依赖旧计划。重复访问列表、保存计划或后台刷新都不会把账单变成资金事实。

## 权限、接口与状态

查看要求 `statements.read`，保存要求新增的 `statements.schedule`；仅管理员和财务拥有。生产邮箱验证、匹配的Origin和JSON要求继续生效。保存计划按用途分别限制直接对端IP和当前用户各5次/分钟。全局下载开关关闭时，仍可查看和停用已保存计划；启用返回503，不启动调度或下载消费者，手工导入继续可用。

| 方法与路径 | 请求与结果 |
| --- | --- |
| `GET /api/v1/admin/bill-schedules` | 无查询参数；200返回 `{items}`，包含四项计划 |
| `PUT /api/v1/admin/bill-schedules` | 严格JSON `{provider,kind,enabled,run_at,revision}`；200返回保存后的计划 |

`provider` 只允许 `alipay`、`wechat`；`kind` 只允许 `payment`、`refund`；`enabled` 必须明确为布尔值，`run_at` 为24小时制 `HH:MM`，`revision` 为列表中当前正整数版本。并发保存或过期版本返回409，刷新后重新确认，不会覆盖其他人的修改。错误输入400，未登录401，权限或验证不足403，限流429，开关关闭、商户未配置或数据库故障503；不支持的下载能力409。

响应字段包含 `id`、`provider`、`kind`、`enabled`、`run_at`、`timezone`、`revision`、`state`、`next_bill_date`、`last_enqueued_date`、`last_job_id`、`authorized_by` 和 `updated_at`。初始未授权字段为null；内部账号安全版本、商户指纹和授权代次不返回。`state` 为 `disabled`、`active` 或上述三类暂停原因。完整契约见[OpenAPI](../api/openapi.json)。

## 验收边界

本轮使用本机测试商户响应、合成账单和真实PostgreSQL验证调度与任务衔接，没有配置真实商户、调用真实商户下载或执行真实收款/退款。支付宝经典25列档案仍仅部分覆盖，微信仍仅支持指定SUCCESS/REFUND档案；自动计划不会放宽原始格式、签名、摘要或商户校验。

v14已增加[来源级费用与渠道金额比较](statement-financials.md)，每日下载成功导入时同步保存费用观察。资金流水、账户余额和银行到账核对、更广原始格式及真实商户端到端验收仍待开发或验证。测试结果见[验证记录](verification.md)，整体进度见[交付记录](delivery.md)。
