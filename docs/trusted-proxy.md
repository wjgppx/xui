# 可信代理与限流验收

默认使用 TCP 对端 IP，忽略所有转发头。部署在反向代理后时，设置 `TRUSTED_PROXY_CIDRS` 为逗号分隔的实际入口代理网段，例如仅同机 Nginx 使用 `127.0.0.1/32,::1/128`。不要填客户端网段或整个容器/云网络；其他租户能访问的网段不能作为可信来源。拒绝 `0.0.0.0/0`、`::/0`、无效 CIDR 和超过 32 项的配置。

只有直接 TCP 对端属于名单时才读取单个 `X-Forwarded-For` 头，从右向左跳过可信代理，选择首个不可信 IP。全部地址均可信时取最左项。上游代理应覆盖来自公网的同名头，或正确追加实际对端；防火墙应限制 API 入口只能由指定代理访问。可信链最多 16 个 IP、4096 字节；畸形链返回 400，不能退回任意客户端可控字符串。未配名单、没有该头或来自非可信来源时使用实际对端。

不读取 `Forwarded`、`X-Real-IP`、`X-Forwarded-Proto`、`X-Forwarded-Host` 来决定身份、Origin 或 HTTPS。`PUBLIC_ORIGIN`、生产 HTTPS 与 Secure Cookie 策略仍必须正确配置。可信代理解析仅改变限流身份；请求的原始 `RemoteAddr` 保留。

共享限流存放 PostgreSQL，多实例共用。登录/注册、邮件、公开订阅和财务操作沿用各用途的窗口；MFA 各写用途额外同时限制客户端及账号各 5 次/分钟。改变代理链不能绕过账号桶，换账号也不能绕过客户端桶。数据库故障时拒绝放行。

回归覆盖直连伪造头、IPv4/IPv6 与映射地址、多级链、过宽/畸形配置、多个头和超长链、Origin 不受转发头影响，以及不同真实客户端分别计数、同账号跨 IP 共享额度。角色矩阵由既有 HTTP 测试验证；MFA 门禁叠加在后台权限检查之上，不授予额外权限。持续流量验收工具的节点采样负载不等于登录攻击或全部 HTTP 接口的容量上限；生产应按入口代理、实例数和数据库规格另测。
