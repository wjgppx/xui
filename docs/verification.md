浏览器测试需要控制端、前端和已构建的 `bin/xui-agent`。测试账号使用独立随机标识，节点测试结束时撤销节点并恢复账号为普通用户。完整浏览器流程设定 90 秒总超时，断言仍保留自己的等待上限。截图位于被 Git 忽略的 `web/test-results/`。

前一轮安装脚本已重复执行，没有覆盖现有 `.env.local`。此前已验证 SQLite 依赖的直接下载和 GCC/CGO 构建，Go 模块默认代理下载失败时安装脚本回退至直接下载，继续按 go.sum 校验。Xray 安装器检查固定版本压缩包的 SHA-256 后再解压。数据库测试使用独立 schema，不清理业务表。

当前已验证 SQLite 持久化与真实连接到流量入账、额度撤销的链路。兼容验证覆盖官方 Xray 26.10.21 和 Mihomo 1.19.15 的完整配置。验证仍不包括生产支付、其他客户端或版本、UDP/TUN、持续负载下的崩溃丢数测量、长期稳定性或公网性能。TLS 验证使用本地临时 CA 和真实 Xray 客户端，出站仅放行临时 echo 测试端口，不等于公网部署验收。节点心跳表示控制通道正常，不能视作代理业务已经就绪。

SQLite 新增依赖为 github.com/mattn/go-sqlite3 v1.14.32，首次 C 源码构建较慢。8 项账本测试包括写入触发器失败回滚、容量满、拆分原子提交、摘要确认、身份绑定和重开恢复。慢校验停机测试允许最多 1 秒进程清理时间，并检测 5 秒校验阻塞是否延长旧租约。

订阅兼容测试固定官方 Mihomo 1.19.15，并校验固定 HTTPS 资产 SHA-256（不是上游签名验证）。私有测试 CA 仅在测试客户端配置中安装；错误 CA 拒绝连接，导出配置不关闭 TLS 验证。详见 subscriptions.md。

本轮新增31项普通 Go 测试，涵盖支付协议、配置、存储、HTTP和真实签名通知贯通；普通Go测试共118项，原有5项真实内核用例全部回归。完整后端回归后新增的适配器贯通用例另以 `go test -race -count=1 ./internal/httpapi -run '^TestActualPaymentAdapters'` 执行通过，验证四个渠道ID。邮件验收仅连接本机临时 TLS SMTP 服务，未向外部发送邮件。另实测生产模式缺少 SMTP 配置时启动失败，开发模式正常启动且不运行 SMTP 发送消费者。OpenAPI 0.8 与51个实际 HTTP 操作逐项比对，没有缺失或多余接口。浏览器回归包含真实启动的后台消费者，并等待新节点组事件显示“已投递”；它仍不等于节点实际应用。

上一轮已修复邮件 fragment 同页跳转，本轮继续覆盖。新增4项支付界面fixture与原7项业务用例统一回归，11项全部通过（4.8分钟）。先前在开发服务运行时出现页面加载缓慢和事件状态断言超时；数据库证据显示对应事件约0.95秒完成投递。最终改为运行已构建产物的 Vite preview 后完整通过，未放宽测试总时限或断言。README与CI已同步该启动方式，日常开发仍使用dev服务。

支付协议测试使用临时RSA密钥、AES-GCM加密通知和本机TLS网关。真实商户凭据未配置，没有调用真实商户下单、扣款或退款；不代表支付宝官方沙箱、微信商户产品或任意易支付服务商已验收。支付界面通过路由fixture验证，与真实验签/数据库测试分开记录。
