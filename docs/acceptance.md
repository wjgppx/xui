# 压力、网络恢复与持续运行验收

`scripts/test-acceptance.sh`运行独立的流量入账验收负载。它使用随机PostgreSQL测试schema、私有SQLite账本、真实回环TCP echo和控制端HTTP处理器，不连接生产节点，不向公网发送测试流量，也不会清理业务表。

默认样本为4个独立节点工作线程、10秒生成时间、200毫秒采样间隔。每个线程持续发送并校验回环TCP应用负载，将实际写入/读回字节作为累计计数器，持久化到SQLite，再通过真实`/agent/v1/usage-batches`接口提交到同一权益周期，验证多节点并发扣减。

每个节点前两次提交模拟控制端不可达；在尚有待投递批次时关闭并重新打开SQLite；恢复网络后，第一次成功提交已在数据库落库，但丢弃其确认响应。随后必须使用原批次重放，只有匹配的持久确认才能删除本地批次。测试结束时补交剩余批次，比较以下证据：

- 实际回环TCP应用负载字节。
- 成功持久化采样的累计字节。
- 服务端不可变`usage_batches.payload`内的字节合计。
- `usage_items`归属明细的字节合计。
- 权益周期`used_bytes`。

上述合计、唯一批次数、预期重放数和本地待投递数量必须一致。控制端网络中断不代表代理链路断流；本验收的故障注入发生在计量投递边界。实际进程被`SIGKILL`后的WAL恢复由SQLite崩溃测试另外验证。

## 运行

使用现有开发环境：

```bash
bash scripts/test-acceptance.sh
```

更长的重复采样负载：

```bash
XUI_ACCEPTANCE_DURATION=30m XUI_ACCEPTANCE_WORKERS=4 bash scripts/test-acceptance.sh
```

时长接受单个数字及`ms`、`s`、`m`、`h`单位，限制1秒至24小时；线程数1至32，采样间隔`XUI_ACCEPTANCE_INTERVAL`限制100毫秒至10秒，且生成时长至少允许四次采样。延长时间和增大线程数会增加本地数据库、CPU、磁盘及回环流量；应在容量合适的独立验收环境执行。持续24小时的高并发样本会生成大量不可变批次，不能把它当作免费健康检查。

脚本为Go测试设置“请求负载时长加120秒”的总上限。负载时长不包含准备schema、收尾补交和清理时间，JSON报告会记录实际开始、结束和经过时间。

默认报告保存在Git忽略的`.local/acceptance/`，目录0700、文件0600；也可用`XUI_ACCEPTANCE_REPORT`指定不存在的目标文件。目标不能覆盖已有文件或跟随文件符号链接。报告不包含账号、节点令牌、数据库连接串或批次个人标识。

## 报告口径

报告保存真实样本数量、测得字节、持久化/入账合计、账本重开次数、故障注入次数、重放请求数、未交批次以及有限失败代码。`observed_unpersisted_payload_bytes`只比较这次样本中实际观察的应用负载与成功采样字节；即使其为零，也不能推论未观察的内核崩溃窗口没有丢失。

延迟是一次`FlushUsage`调用的总时长，可能包含多批补报；p50/p95采用固定桶上界；超过10秒的溢出桶使用本次实际观测最大值作为上界，并单独记录最大时延和超过10秒的样本数。它不是精确的逐HTTP请求分位数，也不是公网SLA。`elapsed_seconds`记录本次实际测量持续时间；短时通过不能证明长期生产稳定性。

此工具没有通过Xray产生或采样TLS封装流量，因此不测量协议开销、真实内核与应用负载的差额、跨公网质量或未采样崩溃损失。真实Xray/Mihomo连接与更新连续性由内核集成测试验证；长期运行应结合该工具、真实节点和部署环境观察，分别记录时长及边界。
