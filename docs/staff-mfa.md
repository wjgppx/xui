# 后台账号二次验证

后台角色 `admin`、`support`、`finance`、`operator` 支持本地 TOTP 验证器和一次性恢复码。普通用户保持现有登录流程；二次验证不会增加角色权限，后台接口仍先检查权限和生产环境邮箱验证。

## 配置与上线

生产模式默认 `REQUIRE_STAFF_MFA=true`，启动时必须配置 `MFA_KEY_FILE`。文件内容是 32 字节随机密钥的十六进制文本，允许末尾换行；必须是私有普通文件，禁止符号链接和组/其他用户权限。服务启动后在内存中保留密钥副本。

例如，在受保护目录内创建一次密钥（不要覆盖已有文件，也不要提交到仓库）：

```sh
umask 077
set -C
openssl rand -hex 32 > /secure/location/mfa.key
```

将文件所有权授予实际运行服务的账号，并配置：

```dotenv
MFA_KEY_FILE=/secure/location/mfa.key
REQUIRE_STAFF_MFA=true
```

开发模式默认不强制启用；未配置密钥时页面显示二次验证不可用。迁移期间可显式设置 `REQUIRE_STAFF_MFA=false`，让尚未绑定的后台账号继续使用密码登录。已绑定账号始终需要二次验证，此开关不能绕过已有因子。

密钥需要独立、加密备份，并与数据库备份配套管理。自动生成启动密钥、自动轮换密钥和在线重新加密尚未实现。不要更换文件来“重置”验证器：错误或遗失的密钥使原有密文无法解密，恢复码也不能绕过这种故障。

## 账号流程与有效期

1. 使用密码登录，在“账号安全”中输入当前密码开始绑定。服务返回本地 `otpauth://` 地址和手动录入密钥；不要将这些内容交给第三方二维码网站。
2. 使用验证器生成的 6 位数字确认。待确认设置仅对发起绑定的会话和账号安全版本有效，10 分钟过期；已绑定因子不能用密码直接覆盖。
3. 确认成功后撤销此账号的全部旧会话，发放新的已验证会话，并只返回一次 10 个恢复码。妥善保存恢复码，页面刷新后无法取回原文。
4. 后台验证有效期为 15 分钟，最长不超过会话原有到期时间。过期后后台接口返回 `403` 和 `mfa_required`；未绑定但策略要求绑定时返回 `mfa_enrollment_required`。账号安全与退出接口仍可使用。
5. 再次验证可使用 TOTP 或一个恢复码。TOTP 为 SHA-1、6 位、30 秒周期，允许前后各一个周期；服务以数据库时间为准，要求主机时间同步。已成功使用的时间步不能再次用于其他会话，需等待下一个验证码。
6. 关闭二次验证需要当前密码和未使用的 TOTP/恢复码，成功后立即撤销全部会话。强制策略下，下次登录仍须重新绑定。

密码重置和角色变更都会撤销旧会话。密码重置保留已绑定因子，不能用于绕过二次验证；重新登录后仍需提供因子。角色变更使旧的待确认绑定失效。

所有变更按用户锁串行化；恢复码仅保存带用户标识的 SHA-256 摘要，随机码本身提供 128 位熵。TOTP 密钥使用 AES-256-GCM 加密，并通过附加认证数据绑定用户标识。验证码、恢复码和密钥不进入审计内容或错误信息。设置、确认、验证、关闭分别执行每分钟 5 次的共享客户端地址和共享账号限流，数据库不可用时拒绝操作。

## 主机控制台恢复

验证器和恢复码均丢失，或密钥文件不可恢复时，由已经通过主机管理权限认证的操作员执行：

```sh
./bin/xui-control --reset-staff-mfa operator@example.com
```

命令需要有效 `DATABASE_URL` 和现有后台账号；这是本地主机权限边界，没有 HTTP 对应入口，也不需要旧 MFA 密钥。执行后清除该账号的待确认设置、因子和恢复码，递增安全版本并撤销全部会话；强制策略会要求重新绑定。操作写入 `account.mfa_host_reset` 审计事件。应用事件标识目标账号和控制台操作，实际主机操作员身份应由主机访问审计记录。该命令具备数据库迁移能力，只应使用受信任发布版本在受控主机运行。

## 验证记录

`internal/mfa` 覆盖 RFC 6238 测试向量、时间窗、重放、密文篡改和用户绑定。真实 PostgreSQL 测试覆盖会话轮换、同一 TOTP/恢复码并发仅成功一次、待确认绑定失效、审计失败事务回滚、密码重置保留因子、角色变更、控制台恢复。HTTP 测试覆盖强制绑定、15 分钟过期、恢复与关闭、缺钥失败关闭、邮箱与角色限制、严格请求体、来源检查和跨客户端地址的共享账号限流。

以上是自动化验收范围；生产上线仍需使用实际后台账号、实际反向代理与实际密钥备份执行受控验收。
