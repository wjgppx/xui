# 原始账单格式与官方来源下载

控制端0.12 / 数据库迁移v12增加受限原始格式导入、来源记录，以及按需排队的支付宝/微信账单下载。它沿用 [账单差异复核](merchant-statements.md) 的规范记录、快照报告与复核备注，不改变收款、退款、订单、权益或资金任务。v13另外增加默认停用的[每日下载计划](bill-schedules.md)，沿用本页的下载及导入链路。

本轮实现不是所有商户导出格式的通用解析器，也没有连接真实商户验收。支付宝经典格式属于保守的兼容测试档案；微信格式依据公开SDK样例限定版本。未知格式拒绝整批导入，仍可使用规范CSV整理导入。

## 支持的格式

| 格式标识 | 渠道/类型 | 文件与金额来源 | 覆盖范围 |
| --- | --- | --- | --- |
| `alipay_trade_v1` | 支付宝收款或退款 | 经典25列表头，UTF-8或严格GBK CSV；也可上传含一个业务明细文件及可选已知汇总文件的ZIP。使用“订单金额（元）”，收款正值，退款负值取绝对值 | 仅 `partial`，必须存在所选类型记录 |
| `wechat_success_v1` | 微信成功收款 | 现代20列表头，UTF-8 CSV或GZIP；使用“订单金额”原毛额 | `partial`；明确完整声明且汇总通过时可 `full` |
| `wechat_refund_v1` | 微信成功退款 | 现代29列表头，UTF-8 CSV或GZIP；使用“申请退款金额”原毛额和“退款成功时间” | `partial`；明确完整声明且汇总通过时可 `full` |

原始上传请求为严格JSON：`{provider,kind,date,coverage,format,content_base64}`。文件使用标准Base64编码，解码后最多8MiB，压缩展开预算最多8MiB，最多2000条原始/规范记录；转换后的规范CSV仍受1MiB限制。JSON请求最多12MiB。未知字段、坏编码、超限、坏归档、错误金额或日期均拒绝整批，不保留部分结果。压缩内容只在内存解析，不解包到文件系统。

### 支付宝经典档案的限制

`alipay_trade_v1` 只接受固定25列表头及已识别的业务明细结构；可附带业务汇总文件，但该文件不用于证明完整性，不接受个人支付宝消费账单、资金账单、服务商账单或任意新增列。收款按已识别交易行提取，退款按已识别退款行提取；使用完成时间，退款商户编号及渠道对应编号使用“退款批次号/请求号”。不按“商家实收”或扣费净额推断原金额。

当前无法通过可访问的官方原始样例证明全部汇总及空账单语义，因此只产生部分账单。即使下载来源经过验证，也不会升级为完整日账单；没有所选类型记录时不能推断为零交易成功。未知业务类型、未知表头和不明确的空结果均拒绝。真实商户首次使用须用目标商户实际文件和当前文档核对，不能据此声称已兼容所有支付宝原始文件。

### 微信限定档案

仅支持SUCCESS的现代20列和REFUND的现代29列；不接受ALL、旧版缺失毛额列、服务商/子商户或混合商户文件。每行商户号必须一致；官方下载还必须与配置商户号一致。同一直接商户的不同AppID记录可以共同保留，不按当前AppID静默过滤。

数据字段允许已知的前导反引号，尾部必须有已知7列汇总及其值，核对明细数量与毛额合计。未知状态、缺失汇总、截断、合计不符或无法确定的日期拒绝。退款用“退款成功时间”判断账单日期，不能回退使用原支付的“交易时间”。“应结订单金额”和结算口径“退款金额”不等同本平台原收款/退款金额，因此不用于替代毛额。

手工上传默认应选择部分账单。选择完整账单仍是操作者对文件覆盖范围的声明，文件结构和汇总校验不能证明商户下载渠道及完整范围。官方下载微信账单在身份、摘要、档案与汇总全部通过后使用完整覆盖；反向差异仍只是 [本地确认日期候选](merchant-statements.md)，不能直接认定资金缺失。

## 来源记录

每个账单详情增加 `sources`，展示最近20个不可变来源。来源包含格式、`upload`或`download`、SHA-256摘要、完整性标签、商户身份指纹、下载任务关联、导入人和时间。相同渠道、类型、日期、覆盖范围和规范内容仍复用原账单及报告；不同原始来源可追加来源及审计，不覆盖历史内容或自动新建对账版本。

| 完整性标签 | 含义 |
| --- | --- |
| `unverified_upload` | 人工上传；包括既有规范CSV和原始文件，不能当作支付机构验签结果 |
| `wechat_signed_sha1` | 下载元数据验签，文件按微信协议核对解压后的SHA1 |
| `alipay_signed_url` | 下载地址来自支付宝验签响应，通过限定HTTPS地址下载；不代表ZIP本身具有独立支付签名 |

来源摘要与账单规范内容摘要用途不同。规范CSV来源保留规范内容摘要，原始上传保留进入解析链的实际文件字节摘要，包含上传ZIP/GZIP；微信官方下载保留已校验的解压文本摘要，支付宝下载保留ZIP归档摘要。来源标签只说明下载/导入链路，不授予收款或退款事实权限。迁移为历史规范账单补充 `normalized_csv_v1` 上传来源。

不保存或返回原始文件、文件名、下载URL、URL令牌、商户密钥或验签头。商户身份指纹由渠道、应用与商户身份计算，与密钥内容分离；轮换同一身份的密钥不产生新任务身份。

## 按需官方下载

`BILL_DOWNLOADS_ENABLED` 默认空或 `false`。显式设置为 `true` 并重启后，才允许新下载请求并运行下载消费者和每日调度器；其他值使启动失败。关闭时新下载请求及启用计划返回503，已有任务和计划保留，可查看或停用计划，来源查询及手工导入仍可用。该开关与 `PAYMENT_ACTIONS_ENABLED` 相互独立。

支付宝和微信使用既有 `PAYMENT_METHODS` 商户配置及固定验签密钥。常见易支付没有通用可信账单下载协议，本轮不提供易支付官方下载。浏览器只提交 `{provider,kind,date}`，不能传入URL、令牌或商户身份。日期按北京时间选择昨天或更早、最近90天的日账单；本系统对支付宝也采用90天保守边界，虽然官方接口允许更长历史。

成功排队返回200和任务，不代表账单已经下载或导入。每个渠道、类型、日期、商户身份指纹只有一个任务；重复请求复用它。转人工任务可由当前管理员或财务重新提交，沿用任务ID并更新本次请求人/安全版本、重开核实期限。切换配置商户或应用后，旧身份任务不能继续使用新身份，需人工核对。成功下载的规范导入、来源、生成或复用报告以及完成状态在同一事务提交；失败不留下半批证据。

按需入口之外，v13支持初始停用的[每日计划](bill-schedules.md)，按北京时间配置时间排队、最多补排最近7个已结束业务日期。它不自动重新开启转人工任务，也不改变格式或资金证据边界。长期账单同步、费率和结算余额核对仍为后续工作。

### 支付宝链路

使用RSA2签名请求 `alipay.data.dataservice.bill.downloadurl.query`，参数 `bill_type=trade`、日日期和字符串 `secure=true`；验证命名响应原始字节的签名，再读取短时有效下载地址。生产只访问限定的HTTPS `dwbillcenter.alipay.com/downloadBillFile.resource`，不跟随重定向，也不向下载站转发API Cookie或额外凭据。未知地址或未提供可下载文件都不能变成空账单成功。

支付宝官方SDK说明账单为T+1、通常次日9点前生成，短时地址约30秒有效。每次重试都重新请求签名元数据，不持久化过期地址。ZIP在受限预算内校验并解析；本轮最终仍按经典档案导入部分记录。

### 微信链路

使用APIv3签名请求 `/v3/bill/tradebill`，收款用 `bill_type=SUCCESS`，退款用 `REFUND`，并请求 `tar_type=GZIP`。元数据须通过固定平台密钥验签，且包含支持的SHA1及下载地址。

文件下载请求也签名，生产限于相同官方HTTPS商户API主机的 `/v3/billdownload/file`，拒绝重定向和未知路径。该文件响应按协议没有JSON响应签名；先按预算完整解压并检查GZIP，再校验解压后原始字节的SHA1，随后做商户身份、原始格式、日期、数量和毛额汇总校验。不能把GZIP压缩字节的SHA1与原始文件摘要混用。

## 恢复、权限和边界

消费者领取60秒租约和随机令牌，单次处理总时限25秒，入库另设不超过5秒的子时限，失败收尾事务也限5秒，不跨外部请求持有行锁。请求人角色及 `security_version` 在外呼前和事务入库前复查；被降权、改密或商户配置变化的任务转人工，不绕过授权。取消进程后任务可在租约到期后恢复，旧领取者不能提交本地完成结果。

渠道、验签、存储或账单尚未就绪等错误从30秒退避到最多1800秒，8次错误或7天任务期限后转 `manual_required`。格式/汇总校验失败、不支持的能力、商户、请求人身份变化或自动计划授权失效则直接转人工，避免对同一不兼容文件反复自动下载；修正配置或格式后可重新提交同一任务，或手工整理为标准CSV。错误只记录有限枚举，不含URL、文件或渠道响应原文。任务状态为 `queued`、`processing`、`waiting`、`succeeded`、`manual_required`；只有 `succeeded` 才带已导入账单关联。后台显示最近100个任务，等待状态显示下次执行时间。自动任务附带可空的 `schedule_id` 关联；内部计划授权代次不返回。计划失效结果为 `schedule_changed`，转人工后由按需入口明确重试时解除旧计划授权关联。

管理员和财务具有 `statements.download`；原始上传沿用 `statements.import`，任务查看沿用 `statements.read`。客服、运维和普通用户拒绝。生产邮箱验证、可信Origin与JSON仍必需；原始上传、下载请求按用途分别限制直接对端IP和当前用户各5次/分钟。官方下载入口没有商户配置返回503，易支付或不支持的下载能力返回409；原始文件格式或其他输入错误400、限流429，数据库故障拒绝操作。

| 新接口 | 请求与结果 |
| --- | --- |
| `POST /api/v1/admin/statements/native` | 原始上传字段；200返回含来源的账单详情 |
| `GET /api/v1/admin/bill-downloads` | 无查询参数；200返回 `{items}` |
| `POST /api/v1/admin/bill-downloads` | `{provider,kind,date}`；200返回持久化任务 |

公开配置增加 `bill_downloads_enabled` 布尔值，完整字段见 [OpenAPI](../api/openapi.json)。不得把上传成功、任务成功或已复核标签当作实际收款/退款证明。

## 协议依据与验收限制

- [支付宝官方SDK请求模型](https://github.com/alipay/alipay-sdk-java-all/blob/74b7a70f34fe9c7cca6b0ec429c7e955ed467c3e/v2/src/main/java/com/alipay/api/domain/AlipayDataDataserviceBillDownloadurlQueryModel.java)：确认日日期、T+1及 `secure=true`。
- [支付宝官方SDK响应](https://github.com/alipay/alipay-sdk-java-all/blob/74b7a70f34fe9c7cca6b0ec429c7e955ed467c3e/v2/src/main/java/com/alipay/api/response/AlipayDataDataserviceBillDownloadurlQueryResponse.java)：短时下载地址与空文件状态字段；未识别状态不当作零交易成功。
- [微信官方Java SDK下载说明](https://github.com/wechatpay-apiv3/wechatpay-java#下载账单)及 [下载扩展](https://github.com/wechatpay-apiv3/wechatpay-java/blob/main/service/src/main/java/com/wechat/pay/java/service/billdownload/BillDownloadServiceExtension.java)：元数据与文件请求分离、文件响应不签名、解压后摘要校验。
- [WxJava公开格式样例](https://github.com/binarywang/WxJava/blob/develop/weixin-java-pay/src/test/java/com/github/binarywang/wxpay/bean/result/WxPayBillResultTest.java)：第三方SDK的列名/档案证据，不是官方商户验收；项目测试使用独立合成数据，不复制其实现。

云环境无法直接读取部分官方文档站点，本轮通过可访问的官方SDK核对协议。支付宝经典原始格式的完整当前商户汇总语义仍未得到官方文件验证，因此保守限制部分覆盖。没有真实商户密钥、没有实际账单下载、收款或退款；本机TLS协议测试不代表官方沙箱、线上商户产品权限或全部文件版本已验收。测试结果由 [验证记录](verification.md) 单独报告。
