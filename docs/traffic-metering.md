# 持久化流量计量

当前链路将 Xray 的累计原始字节转换为 Agent 本地持久化批次，再由控制端按原权益周期入账。计费口径是上行加下行，不是 IP 层带宽、TLS 线缆字节或客户端显示值。门户的“已入账用量”来自控制端已提交的 `used_bytes`，与实时传输存在采样、传输和刷新延迟。

## 采样与本地提交

每个新 Xray 进程使用新的随机实例 ID，包括配置替换、回退和故障恢复。统计主体区分绑定、平台用户和权益周期，避免同一账号在两个入站的用量混在一起。Agent 使用非重置的累计计数查询，正常每 5 秒采样，不因控制端上报退避而暂停本地计量。

首次看到新进程时，累计值从零计算差值，因此启动到第一次采样之间已传输的字节也进入首批。相同实例的累计值倒退会报错，不能自动当成新进程或制造负数。未返回的方向或暂时消失的主体不能清空已有游标。

SQLite 在同一事务内推进累计游标并写入不可变待发送批次，使用 WAL 与 synchronous=FULL 持久化同步。驱动为 `mattn/go-sqlite3`，构建需要 GCC 和 `CGO_ENABLED=1`，不依赖系统 SQLite 开发包。事务失败不推进游标，也不丢弃旧批次。批次带有固定 ID、内核实例 ID、单调序号、采样区间及按绑定/用户/权益周期划分的原始字节。网络重试始终发送原内容；不能重新生成 ID 或改变顺序。只有批次 ID 与内容摘要都匹配的控制端确认，才允许删除本地待发送记录。单次采样按每批最多 100 个条目拆分，所有分片与游标在同一事务提交；当前待发送上限为 10000 批或累计 64 MiB 载荷，达到容量后拒绝采样并停止代理，不静默覆盖旧批次。

默认数据库位于身份文件所在目录下的 `usage/ledger.sqlite`。账本首次使用时绑定控制端地址与节点 ID 的摘要；切换为另一节点或另一控制端会拒绝复用账本，并保留原待发送数据。同一节点正常重启及凭据轮换不改变计费去重范围。SQLite 文件、WAL/SHM 文件和所属私有目录按含业务状态的数据管理，不应删除或复用为其他节点身份。身份轮换前应先处理旧身份的未确认批次；撤销后的凭据无法再上报，需要后续人工核对流程处理遗留账目。

## 控制端入账

`POST /agent/v1/usage-batches` 只接受节点 Bearer 身份。服务器从身份确定节点，校验批次、历史授权和权益归属，不接受节点自行指定账目归属的其他节点。

- 同一节点与批次 ID、内容完全一致时返回原确认，不重复扣减；相同 ID 不同内容返回冲突。
- 节点、内核实例与采样序号也必须唯一，防止换一个批次 ID 重复提交同一序号。
- 按绑定、用户、权益周期验证历史授权。授权历史保留间隔，不能用现在已经取消的授权否认此前合法传输的延迟账目，也不能给从未授权的主体记账。
- 采样区间必须为正且不超过 2 分钟，结束时间最多领先控制端 30 秒。历史授权校验允许 30 秒时钟/测量边界容差；节点与控制端仍须同步时钟。
- 单方向字节不能为负，同一条目上/下行不能全为零。条目相加、跨条目汇总及权益累计均检查有符号 64 位整数溢出。
- 不可变批次、逐条归属明细与权益 `used_bytes` 在同一个 PostgreSQL 事务提交。任一条目不合法时，整个批次不入账。

摘要基于时间规范为 UTC 的类型化 JSON，包含条目顺序。HTTP JSON 请求最大 64 KiB；类型允许最多 1000 条目，实际发送批次还需满足字节大小限制。控制端保留原始证据和明细，便于后续核对；本轮没有开放财务核对、调整或退款界面。

## 额度与周期

只扣减条目携带并经历史授权验证的原权益周期。过期周期的延迟上报不会转移到当前或未来续费周期。上行加下行的实际已发生字节全部保留，即使用量超过套餐额度也不截断为额度上限。

Agent 在协调时先尝试提交待发送批次，再读取期望状态。当前周期已用额度达到或超过总额度后，控制端不再下发该用户；现阶段通过整份 Xray 配置替换关闭旧连接，因此同节点其他用户的连接也会中断。

采样、网络、重试和配置应用都有延迟，额度耗尽不等于在某一个字节上即时截断。失联时最长 60 秒授权租约限制代理继续运行；采集或本地持久化失败时停止代理，防止持续运行却没有可提交的记录。生产规模下的超额上界还需要结合节点带宽、故障时长和配置切换策略验证。

## 重启与丢数窗口

正常配置替换及正常退出在停止旧进程前进行最后一次累计采样，并先写入本地 SQLite。已提交但尚未确认的批次保留，重启后继续发送；控制端确认丢失时，重复发送由幂等入账处理。

这不能消除所有丢数：最后一次查询返回到进程真正停止之间仍有很短的传输窗口；进程崩溃、强制终止、主机故障或租约计时器终止进程时，最后一次成功采样之后的字节可能无法恢复。若计数查询或本地写入本身失败，也无法声称最后字节已经持久化。当前设计保证已经进入本地事务的批次可重试，并不承诺整个代理链路没有任何丢失窗口。

后续需完成持续流量下的重启测量、故障注入、跨节点额度竞争、磁盘恢复和人工核对，再评估无中断更新及更严格的计量策略。已确认批次删除后，旧进程游标与实例元数据目前仍保留；长期节点运行的压缩/保留策略尚待验证。
