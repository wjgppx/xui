# 支付接口接入

控制端0.13 / 数据库迁移v13增加默认停用的[每日账单计划](bill-schedules.md)；v12增加受限原始账单与默认关闭的按需官方下载，见 [原始账单](native-bills.md)；v11增加标准账单导入与差异复核，见 [商户账单](merchant-statements.md)；v10增加默认关闭的支付宝/微信关单和全额退款审批；v9已增加订单时限、自动核实付款和支付异常记录。此前 v8 增加支付宝、微信支付和常见易支付接口。实现包括收银台创建、签名验证、金额核对、重复通知去重及权益开通；没有使用真实商户密钥、创建真实收款或完成服务商端到端验收。生产启用前仍需准备商户和产品权限，并完成小额支付、异常通知和交易核对验收。

## 接入范围

| 渠道 ID | 产品与签名 | 用户操作 | 支付事实来源 |
| --- | --- | --- | --- |
| `alipay` | 支付宝电脑网站支付 `alipay.trade.page.pay`，RSA2 | 跳转支付宝收银台 | 支付宝 RSA2 签名通知或验签后的 `alipay.trade.query` |
| `wechat` | 微信支付 API v3 Native，RSA 请求签名 | 用微信扫描付款码 | 验签并 AES-256-GCM 解密的通知，或验签后的商户订单查询 |
| `epay_alipay` | 常见 `submit.php`、MD5 协议，`type=alipay` | 跳转易支付收银台 | 通过商户号、渠道及 MD5 校验的异步通知 |
| `epay_wechat` | 同上，`type=wxpay` | 跳转易支付收银台 | 同上 |

易支付名称不代表统一标准。本轮按常见 MD5 协议接入，不声称兼容所有同名平台。指定服务商使用 RSA、不同字段或不同查询协议时，需要按其文档添加适配。现有易支付 `api.php` 查询常返回无签名 JSON，且可能要求将商户密钥放入 URL，因此当前适配器不调用它，也不会用该结果开通权益；易支付依靠有效签名的异步通知更新订单。

支付宝采用公钥模式，暂不支持证书模式、手机网站支付或当面付。微信采用一个显式配置的平台验签公钥和标识，可对应平台证书序列号或 `PUB_KEY_ID_*` 公钥 ID；轮换需更新部署配置并重启，不会从未验证响应自动替换信任密钥。不包含微信 JSAPI、H5、APP 或服务商模式。

## 显式启用与密钥

默认 `PAYMENT_METHODS` 为空，支付渠道不启用，用户看不到未经配置的真实收款方式。选择需要的渠道：

```bash
export PAYMENT_METHODS=alipay,wechat,epay_alipay,epay_wechat
```

不必同时开通全部渠道。启用的渠道缺少或使用无效配置时，控制端启动失败；未启用渠道不要求提供其密钥。所有金额使用 CNY 整数分，服务端从原订单快照构造请求，浏览器不能提交支付金额。

| 变量 | 配置内容 |
| --- | --- |
| `ALIPAY_APP_ID` | 支付宝应用 ID |
| `ALIPAY_SELLER_ID` | 该商户的支付宝 seller_id，用于通知归属检查 |
| `ALIPAY_PRIVATE_KEY_FILE` | 商户应用 RSA 私钥 PEM 文件路径，至少 2048 位 |
| `ALIPAY_PUBLIC_KEY_FILE` | 支付宝验签公钥 PEM 文件路径，不是商户自己的公钥 |
| `ALIPAY_GATEWAY` | 默认 `https://openapi.alipay.com/gateway.do`；官方沙箱可设置为 `https://openapi-sandbox.dl.alipaydev.com/gateway.do` |
| `WECHAT_APP_ID`、`WECHAT_MCH_ID` | 与商户产品绑定的应用 ID 和商户号 |
| `WECHAT_MERCHANT_SERIAL` | 商户签名证书序列号 |
| `WECHAT_PRIVATE_KEY_FILE` | 商户 API 签名 RSA 私钥 PEM 文件路径 |
| `WECHAT_PLATFORM_SERIAL` | 与配置验签公钥匹配的平台证书序列号或公钥 ID |
| `WECHAT_PLATFORM_PUBLIC_KEY_FILE` | 微信支付平台验签公钥或对应证书 PEM 文件路径 |
| `WECHAT_API_V3_KEY` | 32 字节 API v3 密钥，用于通知解密 |
| `WECHAT_GATEWAY` | 默认 `https://api.mch.weixin.qq.com`；保持官方 HTTPS 地址，测试使用独立本机 TLS 服务 |
| `EPAY_PID` | 易支付商户号 |
| `EPAY_KEY` | 易支付商户 MD5 签名密钥 |
| `EPAY_GATEWAY` | 易支付网关的 HTTPS 基础地址，适配器在后面追加 `/submit.php`，不要填写完整 submit.php 地址 |

私钥支持 RSA PKCS#1 或 PKCS#8 PEM，公钥支持 PKIX、PKCS#1 或含 RSA 公钥的 X.509 PEM 证书。验签密钥必须来自支付服务商的可信管理渠道。密钥路径可以指向部署平台挂载的私密文件；限制读取权限，不放入 Git，不将文件正文或环境密钥复制到聊天、日志和前端配置。`.env.local` 只用于本地开发，不可作为生产密钥分发方式。

移除 `PAYMENT_METHODS` 中的渠道也会停用该渠道的回调与主动查询，应先处理未完成订单；当前没有“仅暂停新收款、继续接收旧通知”的独立开关。自动核实付款遇到未启用渠道时记录 `provider_unavailable` 并按有界规则处理，不会跳过验签或自行认定付款。

生产模式仍要求 HTTPS `PUBLIC_ORIGIN`、SMTP 配置和已验证邮箱。真实支付商需要能访问该域名的回调路径；本机临时地址不能完成公网异步通知验收。反向代理需转发原始通知正文及微信支付验签头，不添加 JSON 包装、不重写通知数据，也不要用网页登录或站点 Origin 校验拦截渠道回调。

## 订单与回调规则

1. 下单时固定价格、币种、周期、配额和套餐节点组。
2. 第一次选择支付渠道后生成独立支付 ID，该 ID 作为渠道 `out_trade_no`。同一订单重试复用该 ID，不生成多个不同商户订单号。
3. 一个订单固定一个渠道。后续不能切换为其他渠道；选择其他支付方式需新建订单，避免跨渠道并发收款。渠道创建失败时可使用同一订单重试。
4. 已生成的收银台结果优先复用。当前二维码或收银台过期后需新建订单，不自动替换待支付链接；旧链接是否还可付款需以渠道状态为准。
5. 浏览器返回页和用户“已支付”动作都不能开通权益。只有验证过的通知或可信查询结果能够结算。
6. 回调检查商户身份、渠道类型、商户支付 ID、交易号及金额；金额或币种不符时拒绝。微信另校验签名时间窗口、平台公钥标识和加密资源。
7. 支付记录、已支付订单、权益和业务事件在同一数据库事务中提交。重复同一已确认交易返回成功，不重复开通；同交易号换订单、同订单换交易号均拒绝。
8. 合法通知可能在收银台创建响应之前到达；后到的响应不会将已支付状态覆盖为待支付。合法迟到付款仍按已保存的购买快照结算。

订单状态与支付状态分别保存，订单状态为 `pending`、`expired`、`closing`、`closed`、`paid`、`refunded`；支付状态为 `pending`（已固定渠道、等待创建结果）、`ready`（可展示收银台）、`paid`（已经核实并履约）。状态保存在服务端，前端应刷新订单与权益，不能将跳转、扫码或按钮点击当作付款成功。查询暂时失败不会将订单标记为失败或已支付。

已支持支付宝和微信的持久化自动核实付款、后台支付流水、处理结果记录与重新排队。订单在创建30分钟后过期；过期不表示网关已关单，合法迟到付款仍可履约。仅未建立支付意图的订单可以本地关闭，已有支付意图的关闭请求返回409。详细状态、重试和运营操作见 [支付异常处理](payment-operations.md)。

已实现默认关闭的支付宝/微信网关关单、全额退款审批与恢复，见 [资金操作](payment-actions.md)。已增加规范CSV账单导入和差异复核，详见 [商户账单](merchant-statements.md)。已增加受限原始账单和默认关闭的按需官方下载，见 [原始账单](native-bills.md)。已增加默认停用的[每日账单计划](bill-schedules.md)，采用现有下载消费者和导入链路。尚无部分退款、易支付关单/退款、重复收款处置工作台、全部原始CSV适配或完整结算核对。自动补单和人工“核实支付结果”仍是可验签的逐笔查询；账单导入只是差异证据，不能开通权益或发起退款，不等于完整结算对账。易支付不能主动验签查询；未收到通知时需检查服务商通知投递，不能通过后台手工填金额绕过验签。

## HTTP API

| 方法与路径 | 作用 |
| --- | --- |
| `POST /api/v1/orders/{id}/close` | 关闭本人尚未建立支付意图的订单；有支付意图或已经付款时409 |
| `GET /api/v1/payment-methods` | 返回已启用渠道的 ID 和名称，不返回商户密钥或文件路径 |
| `POST /api/v1/orders/{id}/payment` | 当前用户提交 `{ "provider": "alipay" }` 创建或读取该订单固定渠道的支付结果 |
| `GET /api/v1/orders/{id}/payment` | 当前用户读取自己订单的支付记录；未创建时返回 404 |
| `POST /api/v1/orders/{id}/payment/sync` | 提交 `{}`，使用已配置渠道核实该订单支付；易支付无可信查询时返回 502，仍等待通知 |
| `POST /api/v1/payments/notify/{provider}` | 支付宝 form、微信 JSON 或易支付 form 异步通知 |
| `GET /api/v1/payments/notify/{provider}` | 常见易支付 GET 通知；支付宝及微信适配器拒绝此方法 |

浏览器写接口要求会话、JSON 和匹配 `PUBLIC_ORIGIN` 的 Origin；生产创建或核实支付还要求邮箱已验证。创建和核实分别使用共享限流：直接对端 IP 每分钟 10 次、用户每分钟 5 次。读取接口只返回自己的记录。渠道回调使用独立签名认证和正文大小限制，不要求浏览器会话或 Origin。

只有成功处理后才返回渠道成功应答。支付宝和易支付使用文本 `success`，微信返回成功 JSON。验签/数据错误返回失败状态，数据库暂时失败保留失败应答以便渠道重试。服务端不记录原始签名通知正文或将商户密钥返回前端。回调端点应避免在代理访问日志记录完整查询参数，易支付 GET 通知会携带交易签名及业务字段。

## 验收与后续

本机测试使用独立生成的临时 RSA 密钥、AES 密钥和本地 TLS 服务验证请求、通知及异常数据；这不代表已取得真实商户产品权限、官方沙箱连接或收款成功。未提供商户凭据，也没有发送实际支付创建、扣款或退款请求。当前云环境对部分官方文档站点的网络访问受限，协议实现仍需结合目标商户后台当前文档进行最终核对。

启用生产渠道前，分别验证金额和商户信息、有效/无效签名、重复与迟到通知、断网重试、通知先于创建响应、主动查询结果和证书/公钥轮换。实际已执行检查见 [verification.md](verification.md)，完整平台剩余工作见 [delivery.md](delivery.md)。

`BILL_DOWNLOADS_ENABLED` 默认关闭；显式true并重启后才启用已配置支付宝/微信的后台下载。它与资金操作开关独立，下载与来源校验不会开通或撤销权益。下载日期保守限制为北京时间昨天至前90天，当前支付宝格式仅部分覆盖，详情与官方SDK依据见 [原始账单](native-bills.md)。
