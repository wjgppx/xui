# 节点 Agent 0.4

已实现节点身份、VLESS/Trojan TCP + TLS 配置、手工/套餐节点组授权、权益过滤、Xray 独立进程管理和应用结果上报。已接入累计流量采样、SQLite 游标和待发送批次，以及服务端按权益周期入账。当前仍是开发版本：未完成自动签发证书、无中断热更新或真实商户支付验收；支付适配范围见 [payments.md](payments.md)。

## 注册与运行

管理员在“节点管理”创建节点，取得 15 分钟有效的注册令牌。令牌仅在创建或轮换时显示。控制端只保存节点身份令牌的摘要；代理用户凭据需要交给内核，因此单独存储在 node_grants 中，数据库访问权限和备份应按含凭据的数据管理。

Linux amd64 云环境构建并安装已校验的官方 Xray。SQLite 驱动 `mattn/go-sqlite3` 使用 CGO，需预装 GCC 并启用 `CGO_ENABLED=1`；无需另装系统 SQLite 开发包：

```bash
CGO_ENABLED=1 bash scripts/go.sh build -o bin/xui-agent ./cmd/agent
python3 scripts/install-xray.py
```

先准备节点的 TLS 证书：使用真实证书域名，证书名称例如 `node-a`，在自行选定的证书目录放入 `node-a.crt` 和 `node-a.key`。证书及私钥必须是普通文件，不接受符号链接；私钥只允许文件所有者访问（例如 0600）。证书必须尚在有效期内、包含配置的域名，并与私钥匹配。控制端不接收私钥，也不能指定任意文件路径。

首次常驻运行示例（替换域名与证书目录；本地联调可使用字面回环 IP 的 HTTP 地址）：

```bash
read -rs -p 'Enrollment token: ' XUI_ENROLL_TOKEN
export XUI_ENROLL_TOKEN
./bin/xui-agent \
  --controller https://control.example.com \
  --state .local/agent/identity.json \
  --xray /workspace/shared/tools/xray-26.10.21/xray \
  --certificates /absolute/path/to/certificates
unset XUI_ENROLL_TOKEN
```

后续启动省略 `--controller` 和注册令牌，保留同一 `--state`、`--xray` 和 `--certificates` 参数。控制端地址存储在身份文件中。Agent 不接受包含用户密码、路径、查询串的控制端地址，拒绝重定向，验证 HTTPS 证书。

Agent 首先将自己的随机凭据写入 0600 身份文件并同步到磁盘，再发送注册请求。丢失注册应答可在令牌有效期内用同一凭据重试；注册成功后移除本地注册令牌。运行目录要求 0700，并加进程独占锁。每个身份应使用独立目录，Linux 父进程退出保护与正常退出清理负责停止子进程。

不提供 `--xray` 时仅观察空配置；`--once` 用于一次性接入检查，不能与 `--xray` 同时使用，也不提供代理服务。已有非空配置时必须以带内核参数的常驻模式运行。

## 配置和账号授权

1. 在后台节点行点击“代理配置”。最多 8 个入站，每个入站最多 100 个有效授权账号。
2. 配置唯一标识、VLESS 或 Trojan、监听 IP、1024–65535 端口、TLS 域名和证书名称。相同节点不允许端口重复。
3. 选择授权模式：手工模式填写已注册邮箱；套餐模式必须清空用户列表，并由“权限管理”配置节点组与套餐关联。控制端只下发当前生效、未撤销、未到期且数据库已用额度小于总额度的权益；未付款、未来周期、撤销、过期及耗尽周期均被过滤。
4. 保存携带已读取版本号；多人同时修改导致版本变化时返回冲突，需重新读取。保存后后台显示“等待应用”，不能以保存成功代替实际生效。

代理凭据由控制端随机生成，后台配置接口不回传这些凭据，只向对应节点返回必要的授权用户。管理员填写订阅连接地址和端口、节点完成应用后，普通用户可在门户获取订阅。发布字段只用于客户端连接，不改变内核监听配置，见 subscriptions.md。

正常每 10 秒同步；失败指数退避至最多 60 秒。每 5 秒的本地流量采样独立运行，不因网络上报退避而停止。协调时先上报待发送批次，再读取当前权益状态；额度耗尽会使用户移出配置。控制端按配置和有效授权内容计算摘要，授权状态变化时推进版本，仅续租不推进版本。业务事件消费者也会推进相关节点期望版本以提示重新协调；节点拉取始终按当前数据库状态计算授权，不依赖事件投递成功作为授权依据。事件完成与实际应用应分别查看。

## 应用、失联与回退

- Agent 先验证配置、证书和本地文件权限，再执行 `xray run -test`。预检失败保留旧进程及其原租约，报告 `failed`。
- 内容或证书发生变化时停止旧进程、启动新进程，并完成所有入站的 TLS 握手探测。成功后才报告新应用版本。相同配置续租不重启进程。
- 启动失败时，仅在旧授权租约仍有效时尝试恢复上一份配置；回退也要通过 TLS 探测。后台保持新版本失败状态，不能把回退记成新配置成功。
- 每个新启动的 Xray 进程取得新的实例 ID，包括回退和租约到期后重启。累计游标以该 ID 区分进程，首批从零计算已发生用量，不能跨实例延用旧累计值。
- 配置替换会中断该节点的所有现有连接，包括未修改的入站。移除用户后通过替换进程关闭旧连接；没有承诺无中断热更新。
- 授权租约最长 60 秒，且不超过任何已下发权益的结束时间。独立计时器在到期时终止当前进程，配置预检卡顿也不会延长旧授权。控制端恢复后重新拉取并启动。
- 空 bindings 表示停止服务。身份被撤销后，下一次同步拒绝访问并退出；失联时由租约到期停止。撤销并非对远程节点的瞬时推送。
- “已读取”“已应用”“最近心跳”分别展示。应用成功表示当时内核启动并通过本地 TLS 探测，不等于公网、所有客户端或持续健康已验收。

流量统计只在节点回环管理接口开放。CLI 配置代理内核时自动在身份文件所在目录下的 `usage/ledger.sqlite` 使用 SQLite 持久化游标和待发送批次；数据库、WAL/SHM 文件和身份目录均需保留。计数采集或本地提交失败会停止代理，网络失败保留原批次等待重试。正常配置替换和正常退出先进行最终采样，但最后查询到停止仍存在窗口，崩溃或强制停止可能丢失尚未采集的字节。完整边界见 [traffic-metering.md](traffic-metering.md)。

证书续期后替换本地普通文件，Agent 在下一次协调中检测内容变化并重新应用。未完成自动签发、证书吊销检查或多节点无中断升级。

## 验证与升级

```bash
bash scripts/test.sh
bash scripts/test-xray.sh
```

真实内核测试要求 PostgreSQL 与 `XUI_XRAY_BIN`；脚本默认使用已安装的固定版本。TLS 测试使用临时 CA，并验证错误 CA 被拒绝，没有关闭证书验证。仅测试构建包含对临时回环 echo 端口的窄范围出站例外，生产构建保留 Xray 默认的私有目的地址限制。

控制端启动自动追加数据库迁移 v6，保留原用户、订单、节点和身份数据。先升级控制端，再升级 Agent；历史授权表由升级后的配置读取逐步建立，不应凭空补造旧节点未经记录的授权。原 0.2 Agent 只能观察空配置，非空配置会被拒绝。此轮未删除旧数据或实施破坏性迁移；升级前备份仍属于后续正式部署流程。

旧入站缺省保持手工模式，旧订单和权益不补造节点组快照。套餐组只影响新订单，组成员/启用状态会影响已购买组的权益；详见 [access-and-events.md](access-and-events.md)。

浏览器验证包括配置保存、重新读取、清空和节点撤销；运行步骤见 README。详细测试结果见 [verification.md](verification.md)。
