# 当前业务规则

- 币种为 CNY；所有价格使用整数分，额度使用整数原始字节，界面展示 GiB。
- 一个套餐周期为固定 N × 24 小时，首批示例套餐为 30 天，不称为自然月。
- 下单时保存名称、价格、币种、天数、额度和套餐节点组快照；后续套餐调整不改变已有订单。
- 首次支付从当前数据库时间开通；续费排在该用户已有权益的最晚结束时间之后。不同套餐也排队，不中途折算。
- 支付事件、订单已支付、权益、outbox 在同一个 PostgreSQL 事务中提交。
- 重复的同一支付事件仅确认一次；相同事件 ID 换订单、金额或币种会拒绝。已经支付的订单也不能通过另一个事件再次履约。
- 锁住用户行，再锁住订单行，保证同一用户并发购买不同订单时周期不重叠。
- 当前开发支付只允许已登录用户确认自己的订单，由服务端使用快照金额确认；生产模式下接口返回 404。它没有接入支付机构沙箱，不产生真实资金交易。
- 注册默认普通用户，没有默认管理员密码。管理员由本机 CLI 将已注册账号提升，不能通过注册请求传入角色。
- 会话有效期 24 小时，服务端只保存随机令牌的 SHA256 摘要；退出删除会话，改密或角色变更递增会话版本并撤销所有已有会话。生产 Cookie 要求 HTTPS。
- Web 写请求强制校验单一配置的 Origin 和 JSON Content-Type；Agent 写接口通过独立凭据认证并校验 JSON；登录/注册限流基于直接连接的 IP，不信任任意转发头。计数已使用 PostgreSQL 共享存储，反向代理部署仍需设计可信来源名单和地址解析策略。
- 生产模式的新订单、订阅生成/轮换、代理凭据轮换及后台访问要求已验证邮箱；节点期望状态和公共订阅同样排除未验证账号。开发模式保留未验证账号的测试流程。
- 交易业务事件 outbox 已有控制端消费者，它与 Agent 的流量待发送批次不同。事件投递记录、节点期望版本推进和事件完成标记同事务提交；失败退避，5 次失败进入死信，可由管理员重试。投递完成不代表内核已应用。
- 节点拉取和订阅筛选同步计算有效权益：手工模式使用显式名单；套餐模式使用购买组快照、当前已启用组和成员关系。两种模式均排除未生效、已撤销、过期及已耗尽权益。
- 套餐组关联变化只影响新订单，已下单未付款订单仍使用原快照。组成员调整/停用影响已购买该组的当前权益；旧订单不自动补组，手工模式保持兼容。
- 权益撤销不退款、不改变起止时间、不自动提前后续周期；当前没有恢复接口。
- Agent 使用最长 60 秒授权租约，权益过期或撤销在下一次同步生效，失联最迟在原租约到期时停止代理。
- 用量按 Xray 统计的上行加下行原始字节入账到原权益周期。相同节点/批次与相同内容重试不重复扣减，相同内核实例/序号也不能换 ID 重复入账。
- 已发生用量超出套餐额度时按实保留，不截断。额度耗尽的用户在后续协调时移出配置，采样、网络和应用延迟意味着可能超额。
- 延迟批次按历史授权校验，过期权益的合法账目仍进入原周期，不挪到未来续费权益。多条归属、不可变证据和额度变更在同一个事务提交。
- SQLite 游标和待发送批次保证本地已提交的数据可重试；强制终止、崩溃和最后采样到停止的间隙仍可能丢失尚未采集的字节，不能宣称整个链路零丢数。详细口径见 traffic-metering.md。
- 后台已实现管理员、客服、财务和运维的固定权限范围。邮箱验证、找回/修改密码和账号邮件发件箱已实现；二次验证、真实支付、退款和交易核对仍需继续开发。角色矩阵和令牌规则见 security-and-mail.md。

- 订阅令牌只保存摘要，只在生成时回显；轮换/撤销链接不会撤销已下载的代理凭据。用户可单独重置自己的所有代理凭据，由节点下一次协调应用。订阅只发布有效权益、对应模式下的授权、管理员发布且确认应用的节点，详见 subscriptions.md。

完整授权和事件语义见 [access-and-events.md](access-and-events.md)。
