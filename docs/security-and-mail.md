# 账号安全与邮件

账号安全页面提供邮箱验证、修改密码和开发收件箱，登录窗口提供找回密码。后台使用五种固定角色，权限由服务端逐接口判断；隐藏菜单只改善界面，不能代替服务端授权。

## 使用与生产策略

开发模式保留未验证账号的现有购买、订阅和节点测试流程，不连接外部 SMTP。注册后可进入“账号安全”申请验证邮件，在自己的开发收件箱打开链接，再明确点击确认。忘记密码时提交邮箱，不论账号是否存在，都得到相同的受理状态和消息；开发测试可在已登录的本人收件箱查看自己的重置邮件。

生产模式要求 `PUBLIC_ORIGIN` 使用 HTTPS，并启用 Secure Cookie。未验证邮箱可以登录、访问自己的已有记录、申请验证、改密、退出和撤销订阅；不能创建新订单、生成/轮换订阅链接、轮换代理凭据或访问后台。节点期望状态和公共订阅也会过滤未验证账号。已运行节点通过下一次期望状态拉取更新；失联仍受最长 60 秒租约约束，不能视为即时断流。

验证和重置链接将令牌放在 URL fragment 中，前端读取后立即从地址栏清除，不写入 localStorage。打开页面不会自动消费令牌，用户需要提交确认或新密码。不要复制链接到日志或公开渠道。

## 令牌、密码与会话

| 操作 | 规则 |
| --- | --- |
| 邮箱验证 | 32 字节随机令牌，24 小时有效，只能消费一次 |
| 重置密码 | 独立随机令牌，30 分钟有效，只能消费一次；不自动登录，也不自动标记邮箱已验证 |
| 再次申请 | 同账号同用途旧令牌立即作废，未发送旧邮件取消并清除正文 |
| 修改密码 | 先校验当前密码，新密码与旧密码不同；密码长度为 12–72 UTF-8 字节 |
| 密码变更或角色变更 | 增加账号会话版本并删除已有会话，所有设备重新登录 |

令牌表只存 SHA-256 摘要。待发送邮件正文包含必要的完整链接，因此数据库备份仍含敏感内容，应限制访问并保护存储。邮件成功发送、取消或令牌过期后，消费者会清除相应正文；开发模式没有发送消费者，过期邮件不会再展示，但清理策略仍需随部署安排执行。

密码使用 bcrypt，不记录明文。修改和重置密码会撤销尚未使用的重置令牌，并记录审计事件；网页登录会话与代理凭据、订阅令牌分别管理，改密码不会自动轮换已导出的代理凭据。

## 后台角色

| 角色 | 后台权限 |
| --- | --- |
| `user` 普通用户 | 无后台权限，只能访问自己的业务数据 |
| `support` 客服 | 查看最近订单和账号列表 |
| `finance` 财务 | 查看汇总与订单、创建套餐、查看支付流水和重新排队核实、申请退款与验证当前密码后的渠道关单、账单导入/对账/差异复核、按需官方下载及每日计划管理 |
| `operator` 运维 | 节点及入站配置、节点组与套餐组映射、事件查询与重试 |
| `admin` 管理员 | 上述全部权限，以及权益撤销、账号角色管理和验证当前密码后的退款审批 |

`GET /api/v1/me`、登录和注册响应返回 `permissions`，前端据此展示入口。支付流水与重新排队分别要求 `payments.read`、`payments.retry`，仅管理员和财务具备；重新排队不直接认定已付款，详见 [支付异常处理](payment-operations.md)。账号列表只返回 ID、邮箱、角色、验证时间和注册时间，不返回密码、会话或账号令牌。后台不能取消操作者自己的管理员角色，也不能移除最后一位管理员。角色变更有审计，变更目标账号需要重新登录。

首次创建管理员或本机恢复使用已有账号：

```bash
bash scripts/api.sh --promote-admin your-email@example.com
bash scripts/api.sh --set-role staff-email@example.com --role operator
bash scripts/api.sh --demote-admin former-admin@example.com
```

这些命令只能修改已经注册的账号，同样撤销其已有会话。本机维护命令允许恢复/取消最后管理员，需保护执行机与数据库凭据；浏览器接口没有该例外。

## 共享限流与代理边界

计数存放 PostgreSQL，多个控制端实例共用同一固定窗口。数据库错误时拒绝放行，不回退为各实例独立的内存计数。键以摘要保存，定量清理长期过期桶。

| 请求 | 默认窗口 |
| --- | --- |
| 注册和登录 | 相同直接对端 IP 合计 20 次/分钟 |
| 申请验证、找回密码、修改密码 | 按用途分别限制：IP 10 次/分钟、邮箱 3 次/分钟 |
| 提交验证或重置令牌 | 按用途 IP 10 次/分钟 |
| 公共订阅读取 | IP 60 次/分钟 |

当前只读取 TCP 对端地址，忽略 `Forwarded`、`X-Forwarded-For` 等请求头。反向代理部署下多个用户会共享代理 IP 的额度；可信代理来源名单、真实 IP 解析与攻击负载验收尚未实现，部署前需要明确该限制。

## SMTP 配置

生产启动要求 `SMTP_ADDR` 和 `SMTP_FROM`；开发模式使用本人开发收件箱，不启动 SMTP 消费者。

| 变量 | 含义 |
| --- | --- |
| `SMTP_ADDR` | SMTP 服务器 `host:port`，需支持 STARTTLS，例如通常使用的 587 端口 |
| `SMTP_FROM` | 单个发件邮箱地址，不使用显示名称或换行 |
| `SMTP_TLS_SERVER_NAME` | 证书校验主机名；留空时取 `SMTP_ADDR` 的主机部分 |
| `SMTP_USER`、`SMTP_PASSWORD` | 若服务商要求认证，必须成对配置；两者留空可使用已授权的匿名中继 |

凭据通过部署平台的机密环境变量注入，不提交仓库或写入聊天。当前适配器验证系统 CA、证书主机名并要求 TLS 1.2 及以上；缺失 STARTTLS 或证书错误均失败，不退回明文。只支持 STARTTLS，不支持隐式 TLS 的 SMTPS 模式。生产服务商的域名认证、发件权限、配额、退信、收件箱到达率及轮换须单独验收。

## 发件箱与投递边界

账号令牌与邮件在同一 PostgreSQL 事务中写入。消费者每秒推进，使用 `FOR UPDATE SKIP LOCKED` 避免多实例同时处理同一条待发送邮件，单次 SMTP 操作最多 5 秒。失败保存通用错误分类并指数退避，最多 5 次后标记死信；当前没有邮件死信重试管理页面，可重新申请账号邮件或通过受控运维处理。

SMTP 接受邮件与数据库提交不能组成一个原子事务。发送成功但提交失败时可能重复发送，重试使用相同 Message-ID；这提供至少一次尝试，不保证收件方去重。SMTP 接受也不等于最终进入收件箱。已开始的发送可能与链接替换或消费并发，旧邮件仍可能到达，但旧令牌会被拒绝。

当前测试只使用本机临时 TLS SMTP 服务，验证 STARTTLS、证书拒绝、输入校验、取消，以及数据库队列的成功/失败路径；没有连接真实邮件服务，也没有向外部账号发送邮件。最终测试结果见 [verification.md](verification.md)。

## API

| 方法与路径 | 行为 |
| --- | --- |
| `POST /api/v1/me/email-verification` | 登录后提交 `{}` 申请验证；受理 202，已验证返回 200 |
| `POST /api/v1/auth/email/confirm` | `{token}` 消费验证令牌；成功 200，无效/过期/已用返回 400 |
| `POST /api/v1/auth/password/forgot` | `{email}`，对存在和不存在的合法邮箱统一返回 202 |
| `POST /api/v1/auth/password/reset` | `{token,password}` 重置后退出所有会话 |
| `POST /api/v1/me/password` | `{current_password,new_password}` 修改后退出所有会话 |
| `GET /api/v1/me/development-mail` | 开发模式下本人最新 10 封有效待发送邮件；生产返回 404 |
| `GET /api/v1/admin/users` | 管理员或客服查看最近 100 个账号 |
| `POST /api/v1/admin/users/{id}/role` | 管理员提交 `{role}` 变更角色 |

所有浏览器写请求都要求匹配 `PUBLIC_ORIGIN` 的 Origin 和 JSON Content-Type。节点 Bearer 凭据不能用于账号或后台接口。详细响应契约见 [OpenAPI](../api/openapi.json)。

资金操作增量：管理员/财务可查看和申请全额退款、验证当前密码后请求渠道关单；退款审批仅管理员可执行，且需当前密码及锁定安全版本校验。开关和详细权限见 [资金操作](payment-actions.md)。客服、运维、普通用户无这些接口权限。

账单操作分别要求 `statements.read`、`statements.import`、`statements.reconcile`、`statements.review`，仅管理员和财务具备。写入事务复核当前角色并保留审计；导入和复核不修改金融事实，不要求启用资金开关。导入/重跑按用途分别限制IP与用户各5次/分钟，备注各10次/分钟。详情见 [商户账单](merchant-statements.md)。

原始上传沿用 `statements.import`；按需官方下载要求 `statements.download`，仍仅管理员/财务具备。下载任务同时绑定请求人安全版本与配置商户指纹，外呼前及导入事务复查，身份变化转人工。公开配置只返回 `bill_downloads_enabled`；不开启时拒绝新任务与启用计划，并停止下载消费者和调度器，仍可停用计划，手工导入继续可用。上传和下载请求按用途分别限制IP与当前用户各5次/分钟；下载地址、令牌和原文件不持久化或返回。边界见 [原始账单](native-bills.md)。每日计划新增 `statements.schedule`，仅管理员/财务可管理，保存按IP和当前用户各5次/分钟。计划绑定授权人、安全版本和服务端商户身份；身份变化暂停，停用或更换授权代次撤销未完成的自动任务，提交导入时再次检查。执行时间修改保留有效授权与游标；并发保存要求当前revision。详细规则见 [自动计划](bill-schedules.md)。
