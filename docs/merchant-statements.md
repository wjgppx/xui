# 商户账单导入与差异复核

控制端0.11 / 数据库迁移v11增加标准CSV账单导入、收款和退款差异报告、历史版本与复核备注。本页描述规范格式；v12新增受限支付宝/微信原始格式、来源记录及按需官方下载，见 [原始账单](native-bills.md)。易支付仍仅支持规范收款账单，未提供通用官方下载。没有连接真实商户或完成官方账单验收。

## 导入步骤

1. 管理员或财务在“商户账单”选择渠道、收款或退款、账单日期与覆盖范围，下载标准模板。
2. 从商户账单整理成功收款或成功退款记录。使用交易原金额，不使用扣除手续费后的净结算额；收款和退款分别导入，不把退款作为负数收款，也不在收款金额中减去退款。
3. 选择UTF-8 CSV文件并提交。服务端校验全部内容后，在同一事务中保存规范化记录、首版差异报告和导入审计。任何错误都拒绝整批，不会跳过坏行后导入剩余部分。
4. 查看匹配数、差异数和差异详情。经核查后可追加复核备注；它只表示有人复核，不表示资金已经纠正。
5. 支付通知、可信查询或退款任务后来确认了本地状态时，可“重新对账”。系统创建新报告版本，保留旧版本及其备注；不会修改旧报告，也不会自动把旧备注带入新的差异。

导入文件不具备支付机构签名证明权限。本页的规范导入、重新对账和复核不会执行支付机构请求、建立资金任务、结算订单、发放或撤销权益，也不会修改原收款或退款记录。`PAYMENT_ACTIONS_ENABLED` 关闭时仍可使用本功能；真正的关单与退款继续受 [资金操作](payment-actions.md) 中的权限、密码和开关控制。

## 标准CSV v1

每批只包含一个渠道、一种交易类型和一个上海日期。收款支持 `alipay`、`wechat`、`epay_alipay`、`epay_wechat`；退款暂仅支持 `alipay`、`wechat`。

表头必须按下列顺序完全一致：

```csv
payment_id,transaction_id,refund_id,provider_refund_id,amount_minor,currency,occurred_at
```

| 字段 | 收款 `payment` | 退款 `refund` |
| --- | --- | --- |
| `payment_id` | 商户支付单号，即平台支付意图ID，不是业务订单ID | 原商户支付单号 |
| `transaction_id` | 支付机构原收款交易号 | 原收款交易号 |
| `refund_id` | 必须为空 | 商户退款单号，即平台退款ID |
| `provider_refund_id` | 必须为空 | 支付机构退款号；支付宝公钥模式使用对应 `out_request_no` |
| `amount_minor` | 成功收款原金额，正整数分 | 本次成功退款原金额，正整数分 |
| `currency` | 固定 `CNY` | 固定 `CNY` |
| `occurred_at` | 支付机构记录的收款发生时间 | 支付机构记录的退款发生时间 |

以下只是格式示例，示例编号不代表真实交易：

```csv
payment_id,transaction_id,refund_id,provider_refund_id,amount_minor,currency,occurred_at
aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa,202610280001,,,1900,CNY,2026-10-28T10:30:00+08:00
```

退款使用独立文件：

```csv
payment_id,transaction_id,refund_id,provider_refund_id,amount_minor,currency,occurred_at
aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa,202610280001,bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb,channel-refund-001,1900,CNY,2026-10-28T11:30:00+08:00
```

四类标识字段仅允许ASCII，匹配 `^[A-Za-z0-9][A-Za-z0-9._:-]{0,127}$`。非本平台的合法商户编号也允许导入，用于报告“本地不存在”；不会因此建立新的本地支付或退款。退款和收款标识不能为空，只有收款行的两个退款字段必须留空。

金额必须为不带正号、不带小数、不带前导零的正整数，单笔和整批合计均不得超过有符号64位整数上限。文件中不接受元金额、科学计数法、负数、零、千分位或手续费净额。时间使用带明确时区的RFC3339格式，必须落在选定上海日期的半开区间 `[00:00:00, 次日00:00:00)`；允许用其他明确时区表达同一时刻。日期必须为 `YYYY-MM-DD`，年份范围2000–2099。小数秒最多9位；先检查原时刻的日期边界，再转换UTC并截断到微秒，以匹配PostgreSQL精度，摘要和后续重跑使用相同规范时刻。

文件上限1MiB、最多2000条数据，JSON请求上限2MiB。允许UTF-8 BOM与CRLF换行，拒绝非法UTF-8、控制字符、空白行、多余或缺失列、未知表头、坏引号、跨日期数据和重复身份。收款批次的商户支付单号及渠道交易号各自唯一；退款批次的商户退款单号及渠道退款号各自唯一，同一原支付可以列出不同退款。只有表头的空账单也可以导入，例如声明完整日账单当天没有成功交易。

相同渠道、类型、日期、覆盖范围和规范化内容使用同一摘要去重。调整行顺序、BOM、换行方式或等价时区表达不会创建第二批；重复导入返回原批次及其当前报告，不自动重新对账。并发的相同导入或重跑可能返回可重试409，失败请求不留下部分记录；刷新后重试会读取原批次或生成下一个完整报告，不保证所有并发请求都返回200。修改金额、身份、日期或覆盖范围会形成新批次，保留原内容。服务端保存规范化业务字段和摘要，不保存原始CSV文件或客户端文件名。v12账单详情同时返回最近20个来源及完整性标签；新来源可追加审计，规范内容相同仍复用账单与既有报告，详见原始账单说明。

## 部分账单与完整日账单

`coverage=partial` 为部分账单，只逐条比较导入记录，不能据此推断渠道缺少其他本地交易。界面默认此选项。

`coverage=full` 表示操作者确认文件包含该渠道、该类型、该上海日期内的全部成功记录。除逐条比较外，报告还会寻找“本地在本期确认成功、但本账单未列出”的候选项。完整声明来自导入人，系统无法用文件内容证明渠道账单完整。

本地 `paid_at` 与退款 `completed_at` 是平台确认时间，不是支付机构发生时间。延迟通知、跨日查询恢复或渠道日期口径都可能产生候选项。例如渠道在10月27日23:59收款、本地在10月28日00:05才确认，导入10月28日完整账单时可能出现候选项。因此 `local_only` 必须结合渠道原发生日期、相邻日期账单和可信查询复核，不能直接认定资金丢失，也不会据此补单或退款。

逐条匹配不要求本地确认日期与账单发生日期相同；身份与金额等条件一致的迟到确认仍可匹配。收款记录即使原订单已全额退款，仍以保留的原收款凭证参与收款对账；退款另行核对，不把两者净额相抵。

## 报告和差异类型

每个报告读取同一个PostgreSQL一致快照，并记录 `as_of`。它反映当次读取到的本地状态，不承诺其他事务随后不会改变付款或退款状态。对账不锁住金融业务行。完整账单最多检查2000条本地当日确认记录，超限拒绝本次导入或重跑，保留既有报告；不会截取前2000条并声称完整。

| 代码 | 含义 |
| --- | --- |
| `missing_local` | 账单商户支付或退款单号在本地不存在 |
| `provider_mismatch` | 本地记录的支付渠道与本批账单不一致 |
| `identity_mismatch` | 原支付、原交易号或渠道退款号等身份不一致 |
| `amount_mismatch` | 账单金额或币种与本地购买/退款快照不一致 |
| `not_confirmed` | 本地尚未确认收款或退款成功 |
| `local_only` | 本地在本期确认成功、本账单未列出；需核对跨日和延迟 |

一条差异可以含多个代码，详情同时展示本地与账单身份、金额、状态和时间。报告中的行号是规范排序后的记录序号，不是原文件物理行号。差异最多4000条，每页最多100条，可按未复核/已复核筛选。最近100批账单、每批最近20版报告和每条差异最近100条复核备注可从后台读取。

复核备注为1–1000个UTF-8字节，拒绝控制字符，只追加不覆盖；同一操作者对同一差异重复提交相同备注幂等。界面“已复核”只表示存在备注，差异仍计入原报告。修复实际业务状态须走原有验签付款核实或退款审批流程，随后创建新的对账版本。

## 权限与API

管理员和财务分别通过 `statements.read`、`statements.import`、`statements.reconcile`、`statements.review` 查看、导入、重跑和添加备注。客服、运维和普通用户拒绝访问。生产环境要求已验证邮箱；写请求要求会话、匹配的Origin及JSON。数据库事务中再次检查写入人的当前角色，角色变化不会被页面的旧权限绕过。

导入、重新对账各按用途限制直接对端IP与当前用户各5次/分钟，复核各10次/分钟。数据库故障时拒绝操作，不降级为未审计写入。来源、规范记录、报告、差异与备注保留为不可变记录，导入和人工动作有审计。

| 方法与路径 | 请求与结果 |
| --- | --- |
| `GET /api/v1/admin/statements` | 最近100批，`{items}` |
| `POST /api/v1/admin/statements` | `{provider,kind,date,coverage,csv}`；200返回批次、当前报告和历史报告 |
| `GET /api/v1/admin/statements/{id}` | 批次详情、当前报告、最近20版报告 |
| `POST /api/v1/admin/statements/{id}/reconcile` | `{}`；200返回新报告版本 |
| `GET /api/v1/admin/statements/{id}/runs/{runID}/findings` | `review=all\|unreviewed\|reviewed`、`offset`、`limit`；`{items,total,offset,limit}` |
| `GET /api/v1/admin/statement-findings/{id}/reviews` | 最近100条备注，`{items}` |
| `POST /api/v1/admin/statement-findings/{id}/reviews` | `{note}`；200返回备注 |

默认差异页 `offset=0`、`limit=100`，`limit` 范围1–100，偏移不超过4000。除差异分页外，读取接口不接收查询参数；未知、重复或非法筛选均拒绝。请求不接受调用者填写匹配结果、修改金额或标记“已解决”。金额响应字段 `total_minor`、`statement_amount_minor`、`local_amount_minor` 使用精确十进制字符串（缺失侧为 `null`），避免JavaScript浮点数损失整数分精度；CSV输入仍使用整数分文本。完整字段见 [OpenAPI](../api/openapi.json)。输入错误400，未登录401，权限变化403，不存在或错误嵌套归属404，超限或并发冲突409，限流429，数据库不可用503；并发冲突时可稍后重新读取并重试。

## 剩余验收

规范格式导入不等同完整商户结算系统。v12已增加受限原始档案与默认关闭的按需官方下载，详见 [格式与来源边界](native-bills.md)。支付宝档案仅部分覆盖，微信完整汇总校验也不能替代真实商户验收。更多文件版本、每日调度、手续费与结算余额和真实商户逐笔验收仍待完成；不能把原下载文件改名后直接当作规范模板。测试结果见 [验证记录](verification.md)，整体剩余目标见 [交付记录](delivery.md)。
